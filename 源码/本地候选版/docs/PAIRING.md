# 双边最近密集配对（pairing.py）

`dense_settings.json` 的 `pairing_mode` 选择规划器：

- `nearest_pair`（当前车上默认）：本文件描述的配对规划器；
- `legacy`：原来的单边选边 + `width/2` 偏移规划器（`dense_reference.DensePlanner`）。

两种模式共用同一套 PI/PD、安全门和录制。

## 选路逻辑

1. **近点候选**：每侧只取雷达系 `x ∈ [0.12, pair_near_range_m]`、`|y| ≤ pair_max_lateral_m`
   的点。候选行有三种来源，去重后一起打分：
   - 按 `x` 排序的前 2..N 个点；
   - 按到激光的距离排序的前 2..N 个点；
   - 从最近 3 个种子点各沿行向前走最多 N 个点（链式，步长 ≤2 m、转角 ≤65°）。
2. **拟合**：`fit_curve`（圆弧 → 抛物线 → 样条），要求 `|κ| ≤ pair_max_curvature`，
   并裁掉 x 回折的尾巴（`y=f(x)` 插值需要）。
3. **配对打分**：左右候选两两组合，每对先对齐共同 x 域（两侧数据域不重叠时，
   沿各自端切线**有界外推** ≤1 m，这就是"与远点平滑相接"的机制），再算：
   - 近（`pair_weight_near`）：两点行平均距离越近越高；
   - 密（`pair_weight_density`）：两侧点/米密度的调和平均；
   - 相似（`pair_weight_similarity`）：宽度一致性 CV、两侧航向差、曲率差，
     再乘"宽度接近 1.5 m"的因子；
   - 长（`pair_weight_length`）：两侧**实际观测**到的 x 跨度（不外推）；
   - 衔接（`pair_weight_continuity`）：远处锥桶点到两条延长行的最小距离。
   五项按权重求和，权重和必须为 1（`set_param.py` 会校验）。
4. **中心线**：胜出这一对的两条拟合行取平均 `y_c = (y_L + y_R)/2`，
   再沿端部切线/曲率延伸 `≤ pair_max_extension_m`。
5. **瞄准点**：`preview = 0.8 + 0.25v`，按中心线曲率缩短并夹在 `[0.45, 1.1]`，
   沿中心线至少走 0.55 m；横向夹在 `±(track/2 - half_width - margin)`（1.5 m 赛道即 ±0.52 m），
   保证车始终在"两边路线中心线"的中间区域。瞄准点和航向各做 EMA(0.5) 平滑。

## 与旧版的差异

- 不再有左右选边、密度投票、换边锁相和 `start_side`——同一帧扫描永远选出同一对行；
- 不再用单行 + `width/2` 偏移，中心线直接由两侧行给出；
- 直角检测（`detect_right_turn` / `corner_target`）在配对模式下不参与：
  配对模式没有"单边行"，`right_turn` 恒为 False；
- `follow_offset_m`、`corner_offset_m`、`distance_mode` 在配对模式下都不生效（保留只为兼容旧配置）。

## 前瞻与预测（2026-11-09 20:4x）

上一版有三处把"前瞻"废掉了，已改：

- **瞄准距离不再被 1.1 m 压死**：原来 `0.8+0.25v` 在 1.5 m/s 算出 1.18 m 却统一 clamp 到 1.1 m，
  速度项等于不存在。现在 `preview = 0.8 + 0.35v`，只按曲率打折 0.15，夹在 `[0.7, 1.7]`，
  1.5 m/s 时瞄准点约 1.25 m。
- **雷达看得远比用的远**：锥桶距离 p90 4.54 m，而窗口只到 3.6 m。现在
  `pair_near_range_m=4.5`、`pair_window_m=3.0`（路线覆盖车前 ~3 m）。
- **没有曲率前馈**：PD 只对已有误差反应，进弯必然滞后。新增
  `angle_ff_gain=0.5`，前馈角 = `gain × degrees(κ_target × radius × full_steer)`，
  κ=0.5 时约 13.5°，进弯先打舵、不再等误差积累。

**单边兜底**（`pair_single_side`，默认开）：一侧行不可见时，用可见行 + 1.5 m 赛道宽先验
生成中心线继续开，节点把速度压到 0.85 m/s，记录里标 `degraded`。
回放 19:08 那次：无路线帧 13 → **0**，其中 11 帧走兜底；S 弯记录 60/60。

## 起点"两边都看得见却没路线"（2026-11-09 21:0x）

台架 `--observe` 复现：车在中间、两侧都有锥桶，但 79 帧里 0 帧出路线。逐帧拆开是：

- 右侧其实有**两排**锥桶（内排 y≈-0.78，外排 y≈-1.4），
- 旧候选是"按 x 取最近 N 个"，两排混成一行，宽度算成 **2.2–2.9 m**，
- 宽度门槛 0.95–2.05 把**所有**组合都拒了。

改成**按直线一致性成行**：同一侧点里，任取两点定一条直线，只收落在该线 0.25 m 带内的点，
得到互不混合的"行带"；再按点数/跨度取前 6 条拟合。同一帧立刻得到左 (3 点) + 内右 (2 点)、
宽度 **1.47 m**。另加"车必须在配对走廊内"的因子（`at_car`），否则起点会选到外排那对。

修完台架：79/79 帧出路线、宽度 1.54 m、车相对中心线 +0.15 m、PD +1…+8°（不再打满）。

同时修了一个前馈单位 bug：`kappa*radius*full_steer` 本来就是角度，却又套了 `math.degrees()`，
2° 的前馈被放大成 **130°**，把 PD 顶在 ±38° 限幅——这也是之前"转向很钝/很冲"的元凶之一。
