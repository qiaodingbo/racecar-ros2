# 双边近点拟合与位姿记录

当前默认配置使用 `planner_mode=dense` 和 `pairing_mode=nearest_pair`，赛道标称宽度为 1.5 m。

## 路线选择

- 从车头前向坐标 2.0 m 内选取连续 3 帧复核过的锥桶，每侧最多取最近 8 个有效雷达簇中心，生成近点起始、步长连续的候选点链。三帧按编码器和 IMU 位姿对齐，同一锥桶的跨帧匹配容差为 0.16 m。
- 每条点链拟合曲线，沿法线向赛道内侧平移半个标称宽度。左右两条平移曲线在共同实测区间内比较。
- 宽度、方向和曲率通过几何筛选后，按近点支持、点链密度、双边相似性、共同支持长度和后续远点衔接评分。权重依次为 0.24、0.18、0.30、0.19、0.09。
- 宽度用法向几何关系检查。弯道两侧曲率先换算到对应中心线，再比较。
- 入选左右曲线共同产生中心线。历史中心线通过编码器和 IMU 位姿变换到当前车体坐标，在当前观察重叠区域内平滑融合。全部入选点来自当前帧。
- 近段路线确定后，向前搜索到 4.8 m，在左右边缘末端沿切线接续远点候选。远端预览用双侧宽度、方向和近段连接误差筛选。
- 曾在远区观测到的锥桶进入 2.0 m 近区后，从头累计三帧近区观测。它进入有效双边拟合时，还要和已经接受的中心线在重叠段检查横向偏差和方向差。通过的锥桶才能接入控制路线。远端预览独立记录。
- 只在前视目标需要时延伸末端，最多 0.30 m，并记录延伸长度。车速上限还受实测支持长度和近段曲率限制。
- 预测车体包络与当前中心区域比较，并继续使用原有雷达避障检查。
- 双边拟合丢失时进入中位油门恢复等待，最多 0.35 s 或 0.20 m。恢复失败结束本次行驶。

## 直角弯接力

- 用已经确认的入口双边确定车道方向，再寻找与入口近似垂直、间距符合车道宽度的两排出口锥桶。连续三帧确认后进入转弯模式。
- 用车上转向上限和转弯半径标定生成圆弧。规划时检查车体带余量的扫掠包络和原始雷达回波。控制期间按实时位姿跟踪圆弧，使用当前雷达检查下一段扫掠。
- 默认转弯速度设定上限为 0.35 m/s。航向和出口双边都复核通过时交回普通双边跟踪。位姿中断、跟踪偏离或用完当前实测出口支持时进入停车逻辑。
- `dense_plan.corner` 记录方向、确认次数、弧线半径、航向变化和出口交接状态。

拟合与控制使用车体坐标，x 向前，y 向左。雷达安装参数沿用车上标定值，位于后轴中心前方 0.23 m。

## 使用

```bash
cd /root/racecar/tools/s_bend
./run_dense.sh --observe
./run_dense.sh
```

观察模式每次运行约 8 秒，订阅传感器并记录规划结果。驱动模式通过原有入口执行。

## 位姿与全程记录

每次运行在 `records/runs/` 创建独立的 `*.jsonl`，持续记录原始扫描、传感器源时间戳、接收时刻、扫描对应位姿、入选左右点、路线、评分、拒绝原因和实际发出的控制指令。文件约每 0.75 秒刷新一次，强制断电可能丢失尚未刷新的尾部。结束时继续更新兼容旧分析器的 `dense_last_run.json`。

`dense_plan.far_preview` 保存远端候选边界和候选中心线，`revalidation` 保存近区确认数量及本帧接入的原远区点。导图使用棕色虚点线标记远端预览。

位姿由编码器有符号速度与 IMU 航向积分，起点为首次有效输入时的后轴坐标。扫描位姿要求编码器与 IMU 新鲜，短时外推最多 0.12 秒。编码器积分中断会增加 segment 编号，记录明确标注无有效位姿的扫描。

```bash
python3 make_global_map.py records/runs/具体文件.jsonl global_map.png
python3 make_global_map.py records/runs/具体文件.jsonl global_map_segment1.png --segment 1
```

图中叠加原始雷达点、入选左右边界点、规划中心线和估计后轴轨迹。每次导出一个连续位姿片段。

位姿积分会受轮胎打滑、速度比例、IMU 航向偏差和消息延迟影响。绘图使用每帧位姿统一变换扫描，扫描内运动畸变仍会影响高速弯道。记录保留扫描时间与逐束时间参数，便于后续校正。每次运行的元数据包含代码哈希和运行参数。

## 验证范围

离线回放检查路线选择与历史数据兼容性，静态观察检查真实传感器、日志和导图流程。闭环行驶效果需要赛道实测。
